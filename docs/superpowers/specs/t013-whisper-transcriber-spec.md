# Spec: WhisperTranscriber implementation (T013)

## User Scenarios

### Primary user story

As Manuel (the offline voice assistant app), I want the instruction audio captured after the wake word (T011's `AudioCaptureManager`) transcribed locally via whisper.cpp, with the result accepted only when confident enough, so that the rest of the pipeline (RAG, LLM, TTS) only ever acts on a transcription the app actually trusts (FR-005), fully offline.

### Acceptance scenarios

1. **Given** `WhisperTranscriberTest.kt` (T012, unmodified), **When** run against this feature's `WhisperTranscriber`/`WhisperEngine`/`TranscriptionResult`/`TranscriptionOutcome` types, **Then** all 6 existing test cases pass.
2. **Given** a `NativeWhisperEngine` constructed with a path to a whisper.cpp GGML/GGUF model file, **When** `transcribe(audioPcm16)` is called, **Then** it invokes whisper.cpp's `whisper_full` on the audio (converted to the 32-bit float PCM whisper.cpp expects) and returns a `TranscriptionResult` combining every produced segment's text and an overall confidence score.
3. **Given** whisper.cpp produces one or more segments each with one or more tokens, **When** the native bridge computes confidence, **Then** it averages every token's probability (`whisper_full_get_token_p`) across every segment — a single, simple scalar proxy for "how sure was the model", not a per-segment or per-word breakdown.
4. **Given** the native whisper.cpp call fails (`whisper_full` returns non-zero), **When** `transcribe(audioPcm16)` is called, **Then** the engine returns an empty-text, zero-confidence result rather than throwing or crashing — `WhisperTranscriber`'s existing threshold logic (T012) then naturally requests a repeat, with no separate error path needed.
5. **Given** a `NativeWhisperEngine` whose native context failed to load (a bad or missing model path), **When** it is constructed, **Then** construction fails fast (an exception) rather than silently proceeding with an unusable engine.

## Functional Requirements

- **FR-001**: The system MUST add `WhisperTranscriber.kt` at `app/src/main/kotlin/com/manuel/mvp/stt/WhisperTranscriber.kt`, defining `TranscriptionResult`, `TranscriptionOutcome`, `WhisperEngine`, and `WhisperTranscriber` to exactly match the contract already pinned by T012's `WhisperTranscriberTest.kt` (constructor `WhisperTranscriber(engine: WhisperEngine, confidenceThreshold: Float = 0.6f)`; `transcribe(audioPcm16: ShortArray): TranscriptionOutcome`; `TranscriptionResult(text: String, confidence: Float)`; `TranscriptionOutcome.Transcribed(text)` / `TranscriptionOutcome.RepeatRequested`), without modifying that test file.
- **FR-002**: The system MUST add `NativeWhisperEngine.kt` at `app/src/main/kotlin/com/manuel/mvp/stt/NativeWhisperEngine.kt`, a `WhisperEngine` implementation that loads the `manuel_native` shared library (built by T002's CMake harness) and delegates to JNI-declared `external fun`s for init/transcribe/release.
- **FR-003**: The system MUST add the whisper.cpp JNI glue at `app/src/main/cpp/whisper_jni.cpp`, implementing the three native methods `NativeWhisperEngine` declares, calling into the vendored `third_party/whisper.cpp` library (already linked into the `manuel_native` CMake target by T002) via `whisper_init_from_file_with_params`, `whisper_full`, `whisper_full_n_segments`, `whisper_full_get_segment_text`, `whisper_full_n_tokens`, `whisper_full_get_token_p`, and `whisper_free`.
- **FR-004**: The system MUST update `app/CMakeLists.txt` to add `whisper_jni.cpp` as a source of the `manuel_native` target (alongside the existing `manuel_native.cpp` placeholder).
- **FR-005**: The native transcription call MUST configure `language = "es"` and `translate = false` in `whisper_full_params`, since the target users are Spanish-speaking (matching the top-level spec's "responder en español" requirement for the LLM stage, applied here to the STT stage so what gets transcribed is treated as Spanish speech, not auto-detected or translated).
- **FR-006**: `NativeWhisperEngine`'s native `init` MUST fail fast (a Kotlin-side exception) when the whisper.cpp context fails to load (e.g. bad/missing model path) rather than leaving the engine in a half-constructed, silently broken state.
- **FR-007**: The audio conversion from the `ShortArray` PCM16 samples (T011's `AudioCaptureManager` output format) to the 32-bit float PCM whisper.cpp's `whisper_full` expects MUST use standard PCM16-to-float normalization (divide by 32768.0), matching whisper.cpp's own documented usage convention.
- **FR-008**: `WhisperTranscriberTest.kt` (T012) MUST NOT be modified — it is the authoritative behavioral contract for `WhisperTranscriber`/`WhisperEngine`/`TranscriptionResult`/`TranscriptionOutcome`.

## Success Criteria

- **SC-001**: All 6 test cases in `WhisperTranscriberTest.kt` (T012) pass once `WhisperTranscriber.kt` is added, verified via a JVM-runnable check (standalone `kotlinc` + `JUnitCore`, per the project's no-Android-SDK constraint).
- **SC-002**: `WhisperTranscriber.kt` and `NativeWhisperEngine.kt` compile cleanly against each other and against the real `android.*`-class surface needed (none beyond what `System.loadLibrary` requires), verified via standalone compile.
- **SC-003**: `whisper_jni.cpp` is reviewed line-by-line against the real function and struct signatures in the vendored `third_party/whisper.cpp/include/whisper.h` (fetched via `git submodule update --init` in this task, since it wasn't previously checked out) — every whisper.cpp API call used must match that header exactly. This substitutes for an actual native compile, since no NDK/CMake toolchain is installed in this sandbox (same limitation already documented by T002 for the overall native build harness).
- **SC-004**: `app/CMakeLists.txt` still contains valid, parseable CMake syntax after adding `whisper_jni.cpp` as a source (checked by structural review, since `cmake` itself isn't available to configure the project here).

## Clarifications

- 2026-09-14: **Confidence formula**: the average of `whisper_full_get_token_p` across every token of every segment produced by one `whisper_full` call. This is a simple, direct proxy for overall transcription confidence — no separate calibration, no per-word/per-segment breakdown exposed to `WhisperTranscriber` — consistent with the project's repeated preference for the lighter-weight option elsewhere (lexical FTS5 over vector search, an RMS energy threshold over a dedicated VAD model in T011). If field testing later shows this proxy is a poor confidence signal, revisiting it is a T013-scoped follow-up, not a T012 contract change (T012's tests only care about the resulting `Float`, not how it's computed).
- 2026-09-14: **`third_party/whisper.cpp` submodule checkout**: it was registered in `.gitmodules` (by T002) but not yet checked out in this working tree (`git submodule status` showed a `-` prefix). This task ran `git submodule update --init --depth 1 third_party/whisper.cpp` to fetch it, purely to read `include/whisper.h` for writing correct JNI glue against the real API — this is a read-only, non-destructive operation (matching the pinned commit T002 already recorded in `.gitmodules`/the submodule's gitlink), not a new dependency decision.
- 2026-09-14: **No NDK/CMake toolchain in this sandbox**: same limitation already documented by T002 (`task-2-report.md` per its CMakeLists.txt comments) — `whisper_jni.cpp` is written and carefully checked against the real header, but has not been compiled or linked. A real build (and a real device/emulator run against an actual whisper "tiny"/"base" GGUF model) remains pending until a full Android dev environment (NDK + CMake) is available, same as T002's and T010's native/hardware-dependent code.
- 2026-09-14: **Model file / packaging is out of scope**: `NativeWhisperEngine` takes a `modelPath: String` constructor parameter; it does not bundle, download, or resolve an actual whisper "tiny"/"base" GGUF model file. Per the top-level `plan.md`, packaging (bundling under `assets/models/` vs. downloading to internal storage on first launch) is a deployment decision for a later task, not this one — matching how T010 left the actual trained `manuel.onnx` wake-word model as a pending human/training-pipeline artifact (T003's note).
