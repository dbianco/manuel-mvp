## Research

- **Why `Locale` makes this genuinely pure**: unlike every other Android-framework wrapper in this codebase, `TextToSpeech.getAvailableLanguages(): Set<Locale>` returns a JDK type, not an Android-only type — so the "is Spanish available" decision can be extracted into a function with zero Android dependency, testable exactly like `KeywordPrefixParser`/`SpeechEnergyDetector`.
- **Locale matching**: `locale.language.equals("es", ignoreCase = true)` — `Locale.getLanguage()` is documented to always return a lowercase ISO 639 code, so `ignoreCase` is defensive rather than strictly necessary; matches any Spanish variant (`es`, `es-AR`, `es-ES`, ...) since country/variant isn't part of the language code.
- **No fallback behavior decided here**: `SpeechSynthesizer` exposes the Spanish-availability flag but does not itself decide what happens if it's `false` (no exception, no silent no-op assumption) — that's T020's UI-state concern, per spec.md's Clarifications.
